# Installing the CRAFT V&V toolchain

This course needs a Verilog/SystemVerilog simulator (Verilator + Icarus), a
formal stack (Yosys, SymbiYosys, Z3), and a pinned Python stack (cocotb 1.9.2,
pyuvm, pyvsc, cocotb-coverage). There are three supported ways to get it, one
per kind of machine. Pick the row that matches you.

| You are on… | Use | Command to start working |
|---|---|---|
| A **UCF / eustis** machine | the pre-built shared env | `source /opt/course/cocotb-env/bin/activate` |
| **Your own** machine, Nix available | the pinned devshell (recommended) | `nix develop` |
| **Your own** machine, no Nix | a manual venv | see [Path C](#path-c--manual-no-nix) |

Whichever path you use, the Python packages are the **same pinned set** from
`code/requirements.txt` (cocotb is held at 1.9.2 — do not let anything upgrade
it), so your local results line up with the graded runner. Verify any setup
with:

```bash
bash code/setup/verify_env.sh
```

It checks every tool and runs an end-to-end ALU smoke test.

Everything the course writes while it runs — mutated copies of a DUT, simulator
logs, formal work directories — goes in `~/.vvtemp`, never `/tmp`. On eustis you
do not have write access to `/tmp`, so nothing here may use it. To see what has
piled up and clear it:

```bash
cd code
just clean-tmp
```

It lists what is there with sizes and dates and asks before deleting anything.
All of it is regenerated by re-running the step that made it, so clearing it
never costs you work. Set `CRAFT_TMP` if you want scratch somewhere else.

## Path A — University machines (eustis)

IT maintains a shared, tested environment. **Do not install Nix or build your
own venv here** — just activate the shared one:

```bash
source /opt/course/cocotb-env/bin/activate
```

One thing the shared environment does not carry is `just`, the small command
runner the recipes are written for. It is a single file and needs no admin
rights, so you install your own copy once:

```bash
bash code/setup/install_just.sh
```

That drops the binary in `~/.local/bin` and puts that directory on your `PATH`
in `~/.bashrc`, so `just` is still there after you log out. Running it twice
does not install it twice. Then:

```bash
cd code
just test alu          # or, without just:  make -C tb/alu SIM=icarus
```

This is the **canonical** stack the autograder uses (Verilator 5.020, cocotb
1.9.2). If a local result ever disagrees with the grader, reproduce it here.

## Path B — Your own machine, with Nix (recommended)

Nix gives everyone the *same* system tools without hand-installing Verilator,
Yosys, and friends. It is the closest you can get to eustis on your laptop, on
both Linux and macOS.

### One-time

1. Install Nix: <https://nixos.org/download> (the Determinate Systems installer
   turns on flakes for you).
2. If you used another installer, enable flakes once:

   ```bash
   mkdir -p ~/.config/nix
   echo 'experimental-features = nix-command flakes' >> ~/.config/nix/nix.conf
   ```

### Every session

From the repo root:

```bash
nix develop
```

The first entry pins the system EDA tools and then builds a repo-local `.venv`
from `code/requirements.txt` (cocotb 1.9.2, pyuvm, pyvsc, …). Later entries are
instant. When it finishes you will see the `CRAFT | V&V devshell ready` banner,
`PYTHONPATH` already set to `code/lib`, and the venv active.

Prefer it to happen automatically? Install [direnv](https://direnv.net), then in
the repo root run `direnv allow` once (a `.envrc` is provided) and the shell
loads whenever you `cd` in.

No flakes? Use the fallback: `nix-shell` (reads `shell.nix`).

### What Nix pins vs. what pip pins

Nix pins the **system tools** to the `nixos-24.05` release (run
`verilator --version`, `yosys --version` to see the exact patch levels you got).
The **Python stack** is pip-installed from `code/requirements.txt`, so it is
identical everywhere — eustis, Nix, or manual. The graded runner scores against
the canonical eustis/CI toolchain. Grading behavior comes from the pinned cocotb
version far more than from a Verilator patch digit, so a `5.020` vs `5.0xx`
difference does not move your score. If you want a byte-exact local
Verilator anyway, see the commented overlay in `nix/packages.nix`.

For a fully reproducible, shared pin, the instructor runs `nix flake lock` once
and commits the resulting `flake.lock`; everyone then resolves to the identical
nixpkgs revision.

## Path C — Manual (no Nix)

Install the system tools with your OS package manager, then build the venv.

**Debian / Ubuntu / WSL:**

```bash
sudo apt-get update
sudo apt-get install -y verilator iverilog yosys z3 gtkwave \
                        python3 python3-venv python3-pip make g++ git
pip install --user git+https://github.com/YosysHQ/sby   # SymbiYosys (sby)
```

**macOS (Homebrew):**

```bash
brew install verilator icarus-verilog yosys z3 gtkwave python make git
brew install --HEAD symbiyosys      # provides sby (or: pip install the sby driver)
```

**Then, on any OS, build the pinned Python env from the repo root:**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r code/requirements.txt
export PYTHONPATH="$PWD/code/lib"
```

Re-activate `.venv` and re-export `PYTHONPATH` each new terminal (or use
direnv). Package versions from apt/brew drift over time, so if a result differs
from the grader, reproduce it on eustis (Path A) — that is the source of truth.

## Troubleshooting

**`just: command not found` on eustis.** eustis has no system-wide `just`.
Install your own copy with `bash code/setup/install_just.sh`. If you just ran
that and the shell still cannot find it, the install worked and this window has
not re-read your shell config. Run `source ~/.bashrc`, or open a new window.

**`cocotb` got upgraded to 2.x / Verilator errors about `--build-jobs`.** Some
extras (e.g. `cocotbext-*`) pull a newer cocotb. Re-pin:

```bash
pip install "cocotb==1.9.2" "pyuvm==2.9.1"
```

**Nix venv suddenly broken after `nix-collect-garbage`.** The `.venv` was cloned
from a store Python that got collected. Just re-enter the shell — the hook
detects it and rebuilds `.venv` automatically. (Or `rm -rf .venv && nix develop`.)

**`nix develop` says flakes are disabled.** Enable them (see Path B one-time),
or use `nix-shell`.

**`sby: command not found`.** SymbiYosys is separate from Yosys. On Nix it is the
`symbiyosys` package (already included); manually, install it as shown in Path C.

**Do I need to install anything for the submission portal?** No. The portal is
a website. It scores your suite against the released pool on its own machines.
Everything on this page is for running simulations locally.
