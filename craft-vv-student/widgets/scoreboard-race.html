What this models. The gating in code/dut/fifo.sv, depth 8, FWFT: a write is stored only when not full, a read pops only when not empty, simultaneous read+write leaves the count unchanged, and rd_data shows the head whenever the queue is not empty. The monitor records a word when the interface acknowledges it; the reference queue is that record, in order. With the bug off, a write while full is refused with full high — the monitor sees the refusal and records nothing, so the two queues cannot diverge. With the bug on, the acknowledge no longer consults full: the word enters the reference queue and never enters the hardware. The reference predicts full as occupancy ≥ 8 and empty as occupancy = 0.

Why the latency is a law, not an accident. A drain checker convicts on the read that reaches the damage, so its latency is the damage's place in line. This bug files the phantom at the tail — place 9, the worst case. The Session 2 demo plants ignore_full, which lands the damage on the head slot instead: same law, distance collapsed to the next read, and the count compare names it the same cycle either way (just demo 04 s2 1).

Deterministic: word values come from the seed (mulberry32), and the same drive sequence reproduces the same cycles exactly.
