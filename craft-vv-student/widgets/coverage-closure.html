What the model never looked at

The FIFO you drove has carried a planted bug from cycle 0: on a simultaneous read+write, the memory write lands at the read pointer instead of the write pointer. The incoming word is dropped into a dead slot; a stale word ships later. count, full and empty stay correct forever — occupancy tells the truth while the data lies.

The gap, stated

Coverage bounds your ignorance; it does not eliminate it. 100% is a statement about your model: every case the model names was exercised. Correctness is a statement about data, and no bin looks at data — a coverpoint counts that an event happened, never whether its result was right. No bigger occ × op model fixes this; the fault class is invisible to event counting by construction. Closure closes the model. Checks — the scoreboard, the flag compares, next week's assertions — are what close the gap. That is the closure memo HW6 asks for: what my model can see, what it cannot, and why that difference is acceptable.

What this models. One clock per cycle, the gating in code/dut/fifo.sv: a write is taken only when not full, a read only when not empty, a simultaneous read+write leaves the count unchanged. Depth 8, 8-bit data, read-before-write memory order. The stimulus and the 3×4 cross are the ones in code/demos/wk06-s2-closure/step3_weak_model.py; the scoreboard is a reference queue, Week 4's. The planted fault is this widget's own — it is not in the released mutant pool.
